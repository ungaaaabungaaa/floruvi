# Public media release: 18 November 2026

## Storage and delivery

- Public bucket: `flourvi`. Object prefix: `flourvi/`.
- Public host: `https://images.floruvi.com`. TLS 1.2 minimum. The R2 development URL is disabled.
- 991 objects: 974 local artwork files, 11 public Convex product files, and six existing testimonial portraits. All uploaded bytes passed SHA-256 checks. All 991 CDN URLs returned HTTP 200 with `Cache-Control: public, max-age=86400`. The 11 product files also passed full public CDN checksum checks.
- Cloudflare Cache Rule `FLORUVI images — one day` applies only to this host and prefix. Edge cache respects the origin cache header. Browser cache respects the origin TTL. A repeat GET returned `cf-cache-status: HIT`.
- Vercel `NEXT_PUBLIC_MEDIA_BASE_URL` and Convex `R2_PUBLIC_BASE_URL` use the public host. No R2 credential is needed by either runtime.
- Product metadata migration checked and updated 11 records. Original Convex file IDs and files remain. Original local artwork remains. Stable Next.js icon endpoints remain on Vercel.

## DNS and cost controls

- Cloudflare Free DNS uses `nelly.ns.cloudflare.com` and `viddy.ns.cloudflare.com`. Website records remain DNS-only. The R2 image hostname uses Cloudflare delivery.
- Apex A records match Vercel's recommended `216.150.1.1` and `216.150.16.1`. Vercel reports no conflict and `misconfigured: false`. The existing Lark MX and TXT records remain.
- Vercel Pro has a saved US$10 extra usage budget with automatic project pausing. This can stop checkout when the threshold is reached.
- Cloudflare has a US$5 usage warning and the existing US$10 account alert. These are alerts, not a hard R2 spending cap. R2 remains usage-based.
- The upload credential is limited to object read/write in this bucket and stored only in a private local file. Never commit it or add it to browser environment variables.

## Validation and remaining work

- Local: 163 tests, lint, and TypeScript checks passed. Production build generated 476 pages.
- Backend: additive schema/functions deployed to the existing production backend. No original data was deleted.
- Packages: compatible security updates include Next.js 16.4.6, MCP server 2.4.0, Exa 2.28.0, and follow-redirects 1.16.2. Two development-only picomatch advisories have no published fix in the checked registry. Do not describe this as a clean audit.
- Website production deployment and live browser checks are recorded in the local release evidence after publishing.
- Next phase: document provider setup and launch gates. Razorpay test/webhook/retry checks, OTP delivery, consent, Meta events, and PostHog funnels still need separate setup and live acceptance. This release does not activate them.

For new artwork, follow [the upload procedure](README.md). Use a new content-hash key. Keep the one-day cache header. Preserve old keys until all references are replaced.
